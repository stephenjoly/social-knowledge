## One-page build specification — proposed policy

**Outcome.** Ask helps turn saved recommendations into a decision. First slice: public airport duty-free listing research for up to three products actually supported by the signed-in owner’s saved captures. This is an intentional extension of current policy, which forbids browsing (`docs/product.md`, Ask policy in `src/ask.ts`, `ARCHITECTURE.md`). Broader archive-linked research remains a later milestone.

**Screens and behavior.** Reuse **Ask / conversation**, **Sources panel**, and **conversation export**; no new workspace or settings screen. Saved fragrance shortlist → “Which can I buy at duty free?” → ask for airport and terminal (and departures/arrivals when material), without searching externally. Once resolved, check public airport/retailer search evidence. Return each product with saved recommendation citations `[1]`, separate web citations `[W1]`, retailer/location applicability, and observation time. Distinguish “listing found in search evidence” from stock; this slice always labels stock **unconfirmed**. Missing listing means “not found in this check,” never “unavailable.” If more than three products need checking, ask which three. Show “Checking public retailer listings…” with existing Stop control. Sources panel separates Saved posts from Web evidence; saved cards open notes, web cards open sanitized external links. Counts read “N saved posts · M web sources.” Prior checks stay dated on reload/export; follow-ups requesting a new check consume budget again.

**Eligibility and privacy.** Add typed `research_archive` planning action with `purpose=airport_retail_lookup`, capture references, bounded product evidence spans, and airport/terminal slots. Backend re-fetches captures with `ownedCapturesByIds(ownerUserId, ids)`, verifies spans against stored recommendation/entity/evidence text, and requires an explicit current or unresolved user-requested listing check. A product name in an unrelated capture is not sufficient task authorization. Reject unrecognized purpose, fabricated/foreign IDs, unsupported product spans, standalone research, coding/execution requests, and instructions found inside sources. Model proposals never grant tools. Missing/irrelevant archive evidence retains current grounded miss; no web fallback. Build queries from validated public product names and user-supplied airport/terminal only, through fixed templates (maximum 300 characters); never transmit full question/history, transcripts, captions, capture IDs/URLs, identity, dates of travel, cookies or credentials. Reject personal/sensitive or instruction-like query slots rather than sending free text. UI explains once that public product/location terms go to a search provider.

**Architecture and source contract.** Inject a provider-neutral `ResearchSearch.search({query, limits, signal})` into Ask; backend runs a fixed bounded search sequence, then passes evidence as untrusted data to the selected answer model. Recommend **Brave LLM Context** first; no model-native browsing or agent loop. The same path serves OpenAI and Cerebras/Qwen. Preserve answer provider/model/thinking metadata; record search provider separately. Keep archive `sources`, `[n]`, `citedCaptureIds` equality/range validation and nullable archive `sufficient` semantics. Add separate `webSources` and `research` metadata; web findings cannot satisfy missing archive facts or inflate saved counts. Research answers are buffered until schema, citations and URLs pass validation, then emitted using existing delta/completion flow. Status streams immediately. No unchecked model URL becomes a rendered link.

**Acceptance and exclusions.** Synthetic saved fragrance → clarification → dated public listing evidence works with either answer provider; Stop, retries, reload/export and owner switching preserve isolation and provenance. Mocked adversarial/network/budget matrix below passes plus `npm run check`; one disposable PR preview verifies desktop/mobile. Excludes direct page fetching, stock guarantees, price guarantees, shopping/reservations, account changes, arbitrary URLs, shell/code tools, autonomous background work, general web research and changes to read-only MCP capabilities. Search extracts may be stale: never claim pages were opened or live inventory checked.

## Enforced budget and lifecycle contract

Proposed defaults, enforced in code/SQLite, never only in prompts. Operator enable flag defaults off; missing key or unapproved provider terms fails closed.

| Boundary | Hard default |
|---|---|
| Logical research turn | At most 3 products and **3 external requests total**, including retries/replays; no automatic search retry, pagination, crawl, Extract or provider fallback |
| Search sequence | Up to 1 airport/retailer discovery query, then up to 2 queries covering the three products on relevant retailer domains; report unchecked items explicitly |
| Owner | 6 external requests / rolling hour; 30 / rolling 24 hours; 10 new research turns / rolling 24 hours |
| Instance/key | 100 external requests / rolling 24 hours; 900 / UTC calendar month; lower configured/provider cap wins; no automatic paid overage |
| Concurrency | 1 research attempt per owner across all chats/retries, 2 instance-wide; reject busy immediately, no queue |
| Models | At most 4 model dispatches per attempt including planning and up to 2 compactions; no automatic SDK retries or schema-repair generation; 2,048 output tokens per call, 8,192 total, including reasoning where provider accounts it; 16,000 estimated input tokens per call plus existing context guard |
| Abuse / model retries | Authenticated-owner dispatch ledger: 40 model calls / rolling hour, 100 / rolling 24 hours across Ask, including planners, clarification, failed attempts and manual retries; applies before dispatch so intent classification cannot bypass it |
| Time | Existing 180-second whole-attempt limit unchanged; research phase at most 30 seconds, each search request at most 8 seconds; parent abort always wins |
| Data | At most 5 results/request, 8 unique web sources/turn; 256 KiB decompressed JSON/request, 2,000 characters/excerpt and 12,000 total web-evidence characters; reject oversize/invalid response while reading |

Reserve each dispatch atomically before network I/O in an owner-scoped durable usage ledger keyed to `userMessageId` (logical turn), assistant attempt, dispatch ordinal and timestamps. Reserve an owner Ask-attempt concurrency lease before planning (all Ask turns, since intent is not known yet); acquire the instance research lease and reserve external usage only after eligibility passes. This deliberately extends the owner concurrency guard beyond one conversation. Manual retries share the turn’s three-search ceiling but charge new model dispatches; same `requestId` replay dispatches nothing. Failures/timeouts/cancellation after dispatch still consume usage; crash cannot refund unknown provider work. Expiring leases survive restart without resetting spend. Instance caps cover every user sharing the key. Keep only bounded usage metadata; roll up/prune expired rows while retaining current monthly aggregate. Reject budget exhaustion before dispatch with controlled `research_limit` and next reset time; no retry loop. These token/call bounds constrain cost but are not a dollar guarantee for answer models.

Set `maxRetries: 0` explicitly for capped model/search calls; map output limits to both OpenAI Responses and Cerebras Chat Completions outside diagnostics. If a provider/model cannot honor a cap, do not enable research on that selection. Truncated JSON fails safely without a repair call or silent model switch. Provider quota/auth, timeout, invalid data and unavailable-search outcomes use controlled codes; return an archive-backed partial answer with “couldn’t verify listings” when possible. Persist `research.status=partial|unavailable|limited|complete` independently of archive sufficiency. Cancellation remains cancelled; whole-attempt timeout remains failed. Abort fetch/body reads and release leases in `finally`; reject late callbacks and require pending-attempt compare-and-set before persistence/completion so cancelled/recovered work cannot overwrite final state. No query, key, provider body, URL query string or raw exception enters logs; log controlled codes, counts, durations and opaque attempt IDs only.

## Security and persistence details

- First slice contacts only a fixed HTTPS search API origin, with redirects disabled, no browser cookies or user-selected endpoint. Search-result URLs are data: no server fetch, unfurl, favicon or thumbnail request. HTTPS-only web links, no userinfo, nonstandard ports, localhost/private IP literals or unsafe schemes; strip fragments/tracking parameters. Domain relevance and airport/terminal applicability must be supported by returned evidence; a domain name or rank alone is not authority. Discovery can identify a retailer; prefer domain-restricted listing queries and post-filter results. Where retailer affiliation/location cannot be established, label it unverified and do not claim a match.
- Search excerpts, titles, snippets, URLs, history and compaction are untrusted. Do not follow page instructions, embedded tool requests or links, and never elevate text to system/developer roles. Backend creates source IDs and query templates; model cannot supply endpoints, limits, credentials or extra calls. Unknown web citation IDs, fabricated links, malformed output and cross-namespace markers fail validation. Structured citations establish reference integrity, not automatic truth; stock stays unconfirmed even when snippets say “in stock.”
- Direct fetching is deferred, not accidentally enabled through the social downloader. A later scope must validate every URL and redirect (maximum 2), resolve/reject all non-public A/AAAA addresses including mapped IPv4, loopback, link-local, private/reserved/metadata ranges, and pin validated DNS to the connection while verifying TLS hostname. Revalidate each hop against DNS rebinding; allow only HTTPS/443, no credentials/cookies/auth forwarding, 5-second request timeout, 256 KiB decompressed text-only body, no scripts/browser execution or subresources. Ordinary `fetch` plus a preflight DNS lookup is insufficient. Provider-side extraction still has provider privacy/retention risks.
- Add nullable `web_sources_json` and `research_json` to conversation messages, with defaults projecting legacy messages to `[]`/`null`; use typed validated public projections, not raw provider payloads. Web source: `{id, citation, title, url, provider, observedAt, contentUpdatedAt:null|string, evidenceKind:"search_extract", excerpt}`. Research includes status, purpose and archive anchor IDs; citation markers use backend-assigned `[Wn]`. `observedAt` is search time, not proof of page update or live stock. Store only cited sanitized evidence; no full HTML/raw search response or cross-owner cache. Conversation deletion cascades evidence; usage accounting cannot be reset by deleting a chat. Do not promote web data into captures, source directories or compaction archive IDs. Historical web evidence remains dated context; a fresh check requires fresh budget/evidence.
- Add `webSources`/`research` to the existing SSE `sources` payload and persisted GET projection; update stream reducer/reconciliation, Sources panel, citation links, empty-state copy and Markdown export. Preserve legacy payload handling and authoritative server completion. New research output validation happens before any answer delta; older archive streaming behavior remains covered by existing tests.

## Provider decision evidence — official docs checked 2026-10-23

- **Recommend Brave LLM Context:** standalone search with extracted source chunks and bounded context; API key required. POST keeps query out of request URL. Configure up to 5 URLs, 2,048 context tokens and source metadata; enforce local byte/character limits too. [API and controls](https://api-dashboard.search.brave.com/documentation/services/llm-context).
- Brave advertises Search at **$5/1,000 requests**, $5 monthly credit; storage requires a plan with storage rights. Thus proposed three-call maximum is $0.015/turn and 900/month $4.50 at listed rate before credit, excluding answer tokens. Confirm selected plan’s storage/derived-answer rights and retention/ZDR terms before enabling persisted evidence; marketing claims are not contract verification. [Pricing and storage FAQ](https://brave.com/search/api/).
- **Alternative Tavily:** standalone Search supports basic depth, domain restriction, bounded results and disabling automatic parameters, generated answers, images and raw content. Basic costs one credit; docs list 1,000 free monthly credits without card and PAYG $0.008/credit. [Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search), [credits](https://docs.tavily.com/documentation/api-credits). Its policy allows query reuse and limited third-party search-index disclosure, making minimum public query fields essential; not preferred for this privacy-first slice. [Privacy policy](https://www.tavily.com/privacy), [platform terms](https://www.tavily.com/terms).
- **Avoid native answer-provider coupling:** [OpenAI web search](https://developers.openai.com/api/docs/guides/tools-web-search) is an explicit API tool, not an automatic consequence of model selection. [Cerebras tool calling](https://inference-docs.cerebras.ai/capabilities/tool-use) asks the application to execute functions; it does not supply a search subscription. Neither warrants adding tools to the current adapter. Search remains injected backend data for either answer model.

## Lead review — adjustments required before approval

Discovery is useful, especially the provider-independent adapter, separate source provenance, bounded backend orchestration and no direct URL fetching in the first slice. This is a proposal, not authorization to provision a provider or implement it.

Three changes are required before turning the proposal into the build brief:
1. **Do not make airport duty free the product boundary.** Keep it as the first acceptance scenario. The agreed feature is archive-linked decision support; a narrow technical first slice can target public product/retailer listing checks across locations. Explicitly separate that implementation limit from the longer-term product mandate. Do not silently narrow the approved direction to airport shopping.
2. **Do not limit ordinary Ask as part of this feature.** The proposed all-Ask dispatch ledger, owner-wide attempt lease and blanket 2,048-token cap broaden scope and can regress normal reasoning/parallel chats. Preserve existing non-research behavior. Enforce concurrency, external requests and model budgets for research attempts, including retries, before each dispatch. Any wider anti-abuse policy needs its own evidence and approval.
3. **Do not silently turn comprehensive requests into “pick three.”** Search-call budgets and answer coverage are different. Prefer batching the saved shortlist into bounded searches; show exactly which items were checked and which remain unknown. If the user requests everything and a hard bound prevents it, disclose partial coverage clearly. Never imply exhaustive coverage or require the user to discover omissions through repeated questioning.

The selected provider/key/billing owner and permitted query/evidence retention remain genuine approval decisions. Search extracts support dated listing evidence, not live-stock claims. Buffered validation is an implementation choice to preserve citation integrity, not a reason to ask the user another permission question by itself.

No implementation started. The separate note-viewer mock-up exercise is active in its own workspace; do not change or block it.
