# Redesign preview acceptance

This preview runs the proposed application UI and API. Visual approval alone is not production acceptance. Preview accounts, storage, and credentials are disposable and isolated; production configuration and archive data are separate.

## Verification boundaries

| Journey | Automated evidence | Remaining live staging acceptance |
|---|---|---|
| Login, onboarding, navigation | Backend/session tests and browser journeys | Sign in as each intended role on the candidate staging release |
| AI connections and model selection | Provider adapter tests and provider-settings browser tests with simulated provider responses, including explicit transcription/analysis/Ask diagnostics | Run Test connections with staging-only provider credentials; verify available models, quotas and permissions |
| Capture submission | URL validation, ownership, worker component tests and browser submission | Complete a permitted Facebook and Instagram capture through actual download, transcription, analysis and archive publication |
| Activity | Safe API projection, retry history, pagination, owner scope and browser interactions | Observe the live captures progress and confirm actionable failure feedback |
| Knowledge base | Library API and synthetic note browsing tests | Browse notes generated by the live captures, then export and inspect the isolated archive |
| Ask | Retrieval, cited-answer persistence and streaming tests with simulated generation | Ask about the live staging captures; inspect citations, streaming and follow-up answers |
| Account API keys, OAuth and MCP | Authentication, owner isolation, revocation and OAuth/PKCE tests | Create a staging-only key, call an allowed endpoint, revoke it and confirm rejection; exercise intended external client integration |

Record the full staging commit and results before promotion. Passing local tests or seeing a successful preview deployment does not establish provider connectivity or production health. Production promotion remains a separate owner-approved release with backup and rollback verification under [Deployment model](deployment-model.md).
